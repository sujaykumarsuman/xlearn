Pattern · Week 2

Sliding Window

One of the highest-leverage patterns in interviews: it turns a family of O(n²) substring/subarray scans into a single O(n) pass.

When should I think about this?

You're asked for the longest / shortest / max / min over a contiguous subarray or substring, subject to a constraint (at most K distinct, sum ≥ target, no repeats). If the answer is a range and you catch yourself writing nested loops that re-scan overlapping regions — that redundancy is the window you should slide.

The idea

Keep a window [left, right] and a small piece of state describing it (a count, a sum, a frequency map). Expand right to include new elements; when the window becomes invalid, contract left until it's valid again. Each index enters and leaves the window at most once, so the whole scan is O(n) even though there are two moving pointers.

Two shapes

Fixed window — the size k is given. Slide a constant-width frame and maintain a rolling aggregate (add the entering element, drop the leaving one).
Variable window — the size is whatever keeps a condition true. Grow greedily, then shrink from the left while the window is invalid; record the best valid window seen.

Reusable template

// Variable-size window — longest substring w/o repeats
func longest(s string) int {
    window := map[byte]int{}
    left, best := 0, 0
    for right := 0; right < len(s); right++ {
        window[s[right]]++
        for window[s[right]] > 1 { // shrink while invalid
            window[s[left]]--
            left++
        }
        if right-left+1 > best {
            best = right - left + 1
        }
    }
    return best
}
 
// Variable-size window — longest substring w/o repeats
int longest(string s) {
    unordered_map<char,int> window;
    int left = 0, best = 0;
    for (int right = 0; right < s.size(); ++right) {
        window[s[right]]++;
        while (window[s[right]] > 1) { // shrink while invalid
            window[s[left]]--; ++left;
        }
        best = max(best, right - left + 1);
    }
    return best;
}

The three moving parts never change: expand on the right, shrink while invalid, record the best valid window. Swap the state and the invalid-condition per problem.

Watch out

The window width is right - left + 1, not right - left. This single off-by-one is the most common sliding-window bug — and it's exactly the category flagged as your weak area this week.

Worked example

For s = "abcabcbb": the window grows to abc (best 3), hits a repeat at the second a, shrinks past the first a, and continues. It never re-examines a character it already dropped — that's why it's linear.

Reach for it when…
Contiguous subarray / substring
Longest / shortest / max / min
A monotonic validity condition
Not for non-contiguous subsets
