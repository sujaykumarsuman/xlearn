Conventions every board, in every design sprint

  1. One file per board under design-system/screens/v2/, named exactly as in the tables above (this index is the naming source of truth). A sprint never renames a board or edits index.html or board.css.
  2. Head: the Google Fonts <link> for Inter and JetBrains Mono, then <link rel="stylesheet" href="../../theme.css">, then board.css, then the board's own <style>.
  3. theme.css verbatim. Reuse its tokens and components (ds-btn, ds-card, ds-badge, ds-modal, ds-seg, ds-toggle, xl-side, xl-nav, xl-topbar/xl-crumb, xl-touch, xl-pat, xl-lock, xl-coach/xl-fab, xl-timer, …). Never copy, fork or override a ds-*/xl-* rule. Board-only layout goes in the board's <style> under its own prefix (ab04-*, …). Where the live app uses a class from web/src/styles/app.css (not in theme.css), the board draws a board-prefixed look-alike and names the live class in the notes. Dark theme only; no new colours. Difficulty: Easy = --ds-ok, Medium = --ds-warn, Hard = --ds-err.
  4. Frames. Full-screen frames stack vertically; panel-sized states sit side by side in a .bd-grid. Each frame is a .bd-frame with a .bd-frame__label reading ABnn-Fk · <title> · <state>, and final copy: real strings and real error codes, no lorem ipsum, no "TBD". Sample data is marked as sample in the notes.
  5. Behaviour-notes aside (.bd-notes) on every frame: timers, gates, exact error codes (e.g. 409 assist_confirm_required), the decision it implements (D-number / ADR §), a11y (focus order, contrast ≥ 4.5:1 on text, keyboard, aria-live for status changes, reduced motion) and the < 1024 px layout intent. --ds-muted text is 3.2–3.6:1 on the panels, so it is for non-essential meta only.
  6. Parity and change. A frame that reproduces v1 is tagged parity; a new state new; a flagged copy variant flag; a sub-variant variant. A visible change you'd recommend for a live screen is drawn as a separate alternative frame (.bd-frame--alt) beside the parity frame and listed under "Decisions to confirm" in the PR. The merge freezes the parity frame, never the alternative.
  7. Narrow frames. Every board ends with a section of .bd-narrow frames (390 px) for its key frames.
  8. Static HTML only: no JS runtime, no support.js, no <script type="text/x-dc">. Boards open from disk or any static server. v1 .dc.html boards are references only.
  9. Never leak withheld data (ADR-0027 §1): no pattern chip while an item is live (open attempt, due or live touch, never solved), no hidden inputs, no answers. A pattern shows only once a touch or attempt has concluded, or from the hint stage.
  10. Preview-only: never imported by web/, never //go:embedded, never shipped. Screenshots go to shots/ABnn@1440.png and shots/ABnn@390.png (full page, each ≲ 500 KB).
  11. The freeze is the board PR merging on CI green (D40). The owner may review afterwards; any change to a frozen board is a follow-up design PR. Freeze state is recorded in docs/v2/status.md, not here.
