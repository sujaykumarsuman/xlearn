AB08 · A2 results dock

The dock under the editor (evolving v1's tests panel, Problem.dc.html:289-302) with four tabs: Samples · Submission · History · Feedback. It shows what a Run or a Submit did — and, for hidden tests, only the passed count, the perf bit, the first failure class and bucketed usage. Every typed response the learner can meet has a line here: the grading phases, each verdict, the not-graded states, and the 413 / 429 / 503 limits for course and arena work. Where t4 §8's copy table has a row, the copy is verbatim; the rest is drafted here and listed under "Decisions to confirm".

Board-wide rules t4 §2.3 · §2.6 · t3 §7.4 · ADR-0027 §5

Tone = meaning, always with an icon and words. green ✓ passed · red ✗ a counted failure (WA, TLE, RE, MLE) · amber ⚠ not counted (a compile error, a non-verdict, a limit) · blue in progress or information · neutral — nothing to judge here. Never colour alone. Hidden tests show four things only: hidden {passed, total}, perf: passed | failed | not_run, firstFailure.class and bucketed usage. Never hidden inputs, expected outputs, case ids, ordinals ("test 38"), stderr, stack traces or per-case timing — on any tab, before or after the conclusion (ADR-0027 §5, t4 §2.6). Samples and custom input are public: full detail on a Run, and for samples on a failing Submit.
Status lines are aria-live="polite" in one region per dock; a verdict line is role="status". Focus never moves on a verdict. A new verdict on a hidden tab puts a dot on that tab (and on AB07's Results tab below 1024 px). Polling follows the server's pollAfterMs (500 ms → 1 s → 2 s → 5 s), with ETag / 304; the SPA keeps polling until factsThroughSeq ≥ attemptSeq (the settling phase, F4). Limits never block a course attempt's grading. Closes, give-ups and the one re-grade are exempt from every quota row (t4 §2.3 row 6). Counted submits (course, touch, mock) are never budget-blocked; arena work is budget-counted and shed first by the breaker (t3 §7.4) — so every budget or breaker line says "course submits", and the arena has its own variants (F15). Grader busy (AB11) sits in the dock header whenever the judge reports saturated or a breaker level.

State

  • POST /api/problems/{id}/runs {context, language, parts[], runInput?} → 202, then GET /api/runs/{id} until terminal (800 ms, then 400 ms). A new Run cancels this account's queued Runs in the context.
  • Per sample or custom input the DTO carries {id, status, class, got, sampleExpected, stdout, stderr}: got and stdout ≤ 8 KiB, stderr ≤ 2 KiB, ≤ 64 KiB per Run. Over a cap the block ends with "Output truncated".
  • Passing samples collapse to one line; a failing one opens with its args, got and expected.

Rules

  • Public only. sampleExpected is allowed in Run and sample views, nowhere else. Custom input shows the learner's own output and never a reference.
  • A Run that doesn't compile shows F8's block (diagnostics at learner-file lines only). Runs are never counted and never move AB07's outlook.
  • Sample data: #16's public samples and a sample debug print.

A11y · narrow

  • ✓ / ✗ always travel with "Passed" / "Wrong answer". The case rows are a list; got / expected are a definition grid read in pairs.
  • Output blocks are pre-wrap and scroll inside a 12-line max height; reduced motion changes nothing here.
  • < 1024 px: the Results tab (F18).

Placement

  • A refused request (429 / 413 / 503) shows its line in the dock body, in place of a verdict, as role="alert" (the learner just clicked); the previous verdict stays one click away in History. Breaker lines that describe a standing condition are role="status" and sit above the last verdict until the level clears.
  • While a Retry-After runs, the button it blocks is disabled with the same line as its tooltip and accessible description; it re-enables itself at the time given.

Codes (m3-09 typed pass-through)

  • quota_exceeded{kind, resetAt} · budget_exhausted{window, resetAt} · queue_full · too_many_pending · too_fast{reason?} · shed{reason} — all 429 with Retry-After. "00:00 your time" renders resetAt in the browser's zone.
  • 503 evaluation_unavailable{fallback: self}: the item or judge can't grade; the attempt continues and ends on the self picker (AB07-F11 / F12a). fallback: none (arena): "Auto-grading isn't available right now." (drafted).

Rules

  • Closes, give-ups and the one re-grade are exempt from every row (t4 §2.3 row 6). Counted submits are never budget-blocked (t3 §7.4), hence "Course submits still work" on every budget and breaker line.
  • Numbers are ADR-0035 §4's start values (L9: 200 Runs / 100 counted / 100 arena a day; L12: 10 slot-min an hour); the copy reads them from the response, not constants.
