AB17 · Pointer notes + "correct, with improvements"

The D26 pass review. xLearn AI looks at course passes and at a revision-touch pass whose solution is materially different from the last one it reviewed. When a solution is correct but improvable, the item is marked "correct, with improvements" and gets up to three pointer notes tied to lines of the learner's own code, plus an optional revisit that sits off the five-touch ladder. Notes are advisory: they never change the grade, pass/fail or the revision schedule. They are private (C3, per account and item, erased with the account), collapsed by default, hidden while the item is live, and never on the public profile.

Board-wide rules D26 · D16 · t5 §7 item 2 · t5 §8 · ADR-0027 §1

What is reviewed (D26): a course pass, and a touch pass whose normalized-code fingerprint differs from the last reviewed solution by more than the tuned threshold. A near-identical touch pass is not re-reviewed (F6). The tier is advisory, so it is the first thing paused when spend runs ahead of pace (F8). Shape (t5 §7 item 2): pass_review{pointer_notes[≤3]{note, lines|null}, revisit{suggested, reason|null}}. A note is ≤ 240 characters; lines always falls inside the submission (validator-enforced), and a note with lines: null has no tag. Notes render as plain text: no Markdown, no HTML.
Private (t5 §8): class C3, stored per (account, item) in judge, erased with the account; never in events, digests or the public route. The BFF answers {state: "withheld"} while the item is live, and the SPA doesn't even fetch then. Never touches pass/fail, the grade or the five-touch ladder; the optional revisit is off the ladder and can be removed any time. Data: GET /api/problems/{id}/pointer-notes → {state: available|none|withheld, notes[≤3]{note, lines}, revisit_suggested, revisit_reason, updated_at} · GET /api/attempts/{id}/analysis → status, reason, improvements, baseline_reviewed_at · POST/DELETE /api/problems/{id}/optional-revisit.
