Board-wide rules t4 §4.3 · §6.2 · §6.3 · D15 · D17 · D18 · I8 · ADR-0027 §1

Grading. The key grader runs inline when the learner submits (cadence final). Score = correct / total; weighted_gate@1 with the quiz thresholds clean_pct 1.0, pass_pct 0.8: Clean 6 / 6 · Rough ≥ 80% (5 / 6) · Miss below 80%, a give-up or the deadline. Unanswered questions count as wrong. Quiz items are never provisional. Reveal (withheld, ADR-0027 §1). Keys and rationale appear only after a counted conclusion (a course attempt or a touch). Never while answering, never in Run, never in a mock for an unconcluded item. The arena follows D17 (F11: reveal behind a spoiler confirm, recorded, uncapped) — see "Decisions to confirm". Shuffle. Options are shown in a per-attempt shuffled order (seeded by the attempt id, stable across reloads); order items start shuffled. Recall bands prefer blank probes over MCQ (a 4-option guess is right 25% of the time).
Revisable guard (I8). revisable = role ∈ {core, reinforcement} ∨ (role = drill ∧ revision.drills). Every pilot quiz (gc-004, gc-008) is a drill and go-concurrency sets revision.drills false: no revision line, no touch dots, no mistake entry. They read "Drill · not scheduled for revision". Clock (D15, D18). Start stamps started_at; the deadline is started_at + 45:00. No pause control anywhere. The ring is role="timer", aria-live="off"; one polite region announces "5 minutes left." at 40:00 and "1 minute left." at 44:00. There is no hint stage on a quiz item. Keyboard. Radios and checkboxes are native groups in fieldset/legend (arrow keys, Space). Order: move buttons and Alt+↑/↓. ⌘⇧↵ opens the submit confirm (never submits directly). Give up is never focused first and never bound to a key.

Q1 · RightWhich pair of accesses races?
You: hits++ in one goroutine and hits++ in another
Why: hits++ reads, adds and writes; four goroutines do it with no lock. wg.Wait() orders the final read after every Done, so that read doesn't race.
Q2 · RightWhich primitive fits the increment best?
You: atomic.Int64
Why: one integer, one operation: an atomic add is the smallest correct tool. A WaitGroup waits; it doesn't protect data.
Q3 · WrongWhich changes remove the race?
You: Mutex · atomic.Int64
Answer: Mutex · atomic.Int64 · count locally and send the total on a channel
Why: a goroutine-local count shares nothing until it's sent, and the channel send happens before the receive. runtime.Gosched() only yields; it orders nothing.
Q4 · RightOrder the pool shutdown.
You: close(jobs) → workers return → wg.Wait() → close(results)
Why: close the input first so workers' range ends; close the output only after every sender is done.
Q5 · RightThe type that runs an initializer once.
You: sync.Once
Why: Once.Do runs its function once and makes every caller wait until it has returned.
Q6 · RightPredict the output.
You: 1 / 2
Why: a closed buffered channel still delivers what's buffered; range stops after the last value.
