Why this matters

3Sum is the canonical sort + two-pointers problem. It teaches how to collapse an O(n³) brute force to O(n²) and how to skip duplicates cleanly — a move that reappears in 3Sum Closest, 4Sum, and interval problems. Interviewers love it because the naive answer is obvious and the good answer is not.

Problem

Given an integer array nums, return all triplets [nums[i], nums[j], nums[k]] such that i ≠ j ≠ k and the three sum to 0. The result must not contain duplicate triplets.

Example

// input
nums = [-1, 0, 1, 2, -1, -4]
// output (order within a triplet doesn't matter)
[[-1, -1, 2], [-1, 0, 1]]

Constraints · 3 ≤ n ≤ 3000 · −10⁵ ≤ nums[i] ≤ 10⁵

First thought · brute force

Three nested loops over every i<j<k, keep those that sum to 0, dedupe with a set. Correct but O(n³) time — ~2.7×10¹⁰ ops at n=3000. It will TLE. The set-dedupe also costs memory and hides the real structure.

Key observation

Fix one number nums[i]. The rest is Two Sum for target −nums[i]. If the array is sorted, Two Sum on a sorted array is a two-pointer sweep — no hash map, and duplicates become adjacent so they're trivial to skip.

Pattern recognition

When you see “find combinations in an array that hit a target sum” → sort, then converge two pointers from both ends. Moving left raises the sum, moving right lowers it.

Optimized approach

Sort the array. For each index i, run two pointers l = i+1, r = n-1 toward the target −nums[i]. Skip duplicate i, and after recording a hit, skip duplicate l/r. Break early once nums[i] > 0.

Algorithm steps

  1. Sort nums ascending.
  2. Loop i from 0 to n−3. If nums[i] > 0 break; if nums[i]==nums[i-1] skip.
  3. Set l=i+1, r=n−1.
  4. sum < 0 → l++; sum > 0 → r−−.
  5. sum == 0 → record, then advance both and skip duplicate l/r.

Dry run · sorted [−4, −1, −1, 0, 1, 2]

i=-4  l,r → -1..2  sums -3,-4,-1 → none
i=-1  l,r → -1..2  sum 0 ✓  [-1,-1,2]
      l,r → 0..1   sum 0 ✓  [-1,0,1]
i=0   l,r → 1..2   sum 3 >0 r--  → none
result = [[-1,-1,2], [-1,0,1]]

Reference solution

func threeSum(nums []int) [][]int {
    sort.Ints(nums)
    res := [][]int{}
    for i := 0; i < len(nums)-2; i++ {
        if nums[i] > 0 { break }
        if i > 0 && nums[i] == nums[i-1] { continue }
        l, r := i+1, len(nums)-1
        for l < r {
            sum := nums[i] + nums[l] + nums[r]
            switch {
            case sum < 0: l++
            case sum > 0: r--
            default:
                res = append(res, []int{nums[i], nums[l], nums[r]})
                l++; r--
                for l < r && nums[l] == nums[l-1] { l++ }
                for l < r && nums[r] == nums[r+1] { r-- }
            }
        }
    }
    return res
}
 
vector<vector<int>> threeSum(vector<int>& nums) {
    sort(nums.begin(), nums.end());
    vector<vector<int>> res;
    for (int i = 0; i + 2 < nums.size(); ++i) {
        if (nums[i] > 0) break;
        if (i > 0 && nums[i] == nums[i-1]) continue;
        int l = i+1, r = nums.size()-1;
        while (l < r) {
            int sum = nums[i]+nums[l]+nums[r];
            if (sum < 0) ++l;
            else if (sum > 0) --r;
            else {
                res.push_back({nums[i], nums[l], nums[r]});
                ++l; --r;
                while (l<r && nums[l]==nums[l-1]) ++l;
                while (l<r && nums[r]==nums[r+1]) --r;
            }
        }
    }
    return res;
}
Time O(n²) Space O(1) ex-sort

Common mistakes

  • Forgetting to skip duplicate l/r after a hit → duplicate triplets.
  • Advancing only one pointer on a match (infinite/incorrect).
  • Skipping duplicates before recording the first hit.

Interview discussion & variations

Be ready to justify sorting (O(n log n) is dominated by the O(n²) sweep) and to contrast with a hash-set variant. Follow-ups: 3Sum Closest, 4Sum (add a loop), 3Sum Smaller (count, don't enumerate), and Two Sum II as the sorted primitive.
